## Adicionado

### Alertas: ntfy, SMTP e MQTT

- **ntfy** (`httpx`): publica o texto renderizado em `server/topic` com `Title`, `Priority`
  (mapa severidade→1..5, padrão 3/4/5) e `Tags`; `attach_roi: true` passa a usar `PUT` do PNG
  (`Filename: roi.png`, texto no header `Message`). O token é opcional e só por env (`token_env`;
  vazio = tópico anônimo).
- **SMTP** (stdlib `smtplib`): `security` pode ser `starttls` (padrão), `ssl` ou `none`; as
  credenciais vêm de `username_env`/`password_env` (login só quando a variável de usuário existe) e
  nunca aparecem em erros/logs. `attach_roi` (padrão true) anexa o PNG da ROI.
- **MQTT** (extra opcional): `pip install -e ".[mqtt]"` (não entra nos instaladores). `host`/`topic`
  obrigatórios, `port` padrão 1883 (8883 com `tls`), `qos` 0/1/2, `retain`, `client_id`,
  credenciais por env. Canal configurado sem o extra falha visível com `alert.mqtt_missing_extra` —
  nunca em silêncio. Sem imagem.
- Os três seguem o schema `options:`, `id`/`cooldown_s`/`severity_min`, templates de payload e a
  regra de erros saneados. O `test-alert --list/--only` mostra o destino; o `features --json` informa
  se o extra `mqtt` está instalado.

```yaml
alerts:
  - type: ntfy
    id: celular
    options: { server: "https://ntfy.sh", topic: "meu-topico", token_env: NTFY_TOKEN,
               attach_roi: true }
  - type: smtp
    id: email
    options: { host: "smtp.example.com", port: 587, security: starttls,
               from_addr: "watch@example.com", to: ["oncall@example.com"],
               username_env: SMTP_USERNAME, password_env: SMTP_PASSWORD }
  - type: mqtt
    id: barramento
    options: { host: "10.0.0.30", topic: "screen-watch/default", qos: 1,
               username_env: MQTT_USERNAME, password_env: MQTT_PASSWORD }
```

### Soneca/silenciar e escalação

- **Soneca…** (durações de `ui.snooze_minutes`, padrão 5/15/30/60) e **Silenciar/Reativar** no grupo
  Detecção e alertas, no tray e — para o **Ciente** — na hotkey opcional `ui.hotkeys.acknowledge`. O
  `AlertGate` compartilhado é thread-safe, vale para todas as sessões e persiste no `state.json`
  (`alerts_snooze_until`, `alerts_muted`), então um `run` headless posterior já herda o estado até a
  soneca expirar.
- Com o gate ativo, o `dispatch` devolve `SUPPRESSED_MANUAL` antes de tentar qualquer canal e o
  baseline é mantido: a mudança pendente volta a alertar quando a soneca expirar ou o silêncio for
  desfeito.
- **Escalação**: `defaults.escalation`/`overrides.escalation` (`enabled`, `severity_min`). Com um
  outcome `FIRED` em `severity >= severity_min`, o baseline **não** avança e o alerta repete na
  cadência do `cooldown_s` de cada canal até o **Ciente** (`acknowledge()`), que re-arma o baseline.
  Um rótulo de status mostra "aguardando reconhecimento". O re-arm manual também encerra.
- **Evidência de mudança atrelada à tentativa real**: o `record_change` grava print apenas em
  `FIRED`/`FAILED` (e a cada disparo da escalação), em vez de um por tick enquanto suprimido.

### Ciclo de vida das seleções no CLI (fluxo headless)

- `edit-selection NAME` edita sem overlay: `--mode`, `--roi X Y W H` (reancora
  `origin_at_selection` e limpa os dois campos de máscara), `--mask X Y W H` (repetível, substitui as
  máscaras efetivas), `--clear-masks`, `--poll-interval-s`, `--rearm/--no-rearm`, `--text-watch TEXT`
  `--text-expect appears|disappears`, `--clear-text-watch` e `--clear-override KEY`
  (`mode|poll_interval_s|rearm|masks|text_watch`). Grava atomicamente; em erro o arquivo fica intacto.
- `rename-selection OLD NAME` reusa `plan_rename`/`rename_selection` da GUI (slug, conflito e
  rollback); `remove-selection NAME...` apaga os arquivos e limpa o `last_selection` quando apontava
  para um removido; `list-selections --json` imprime arquivo/nome/ROI/modo/máscaras efetivas/chaves de
  override para scripting.
- O item "Radar" do README está resolvido: `list-windows` → `select-manual` → `edit-selection` →
  `validate-config --selections` → `run --selection` cobre todo o ciclo da seleção.

```powershell
python -m screen_watch list-windows
python -m screen_watch select-manual --handle 123456 --roi 120 340 400 80 --name "painel erp"
python -m screen_watch edit-selection painel-erp --mode advanced --mask 10 10 40 20 `
  --poll-interval-s 1.5 --text-watch "CONCLUÍDO" --text-expect appears
python -m screen_watch validate-config --selections
python -m screen_watch run --selection painel-erp
```

### Múltiplas ROIs na GUI

- O novo `gui/session_manager.py::SessionManager` roda **N sessões** (um `MonitorLoop`/thread/backend
  e buffers de preview/calibração por seleção) com `AlertGate` compartilhado. O `MonitorController`
  foi removido (sem shim de depreciação).
- A lista de seleções tem **checkboxes**: Iniciar inicia todas as marcadas (nenhuma marcada = a linha
  destacada). Linhas ativas ganham prefixo `▶`, o status agrega a contagem, logs/resultados são
  prefixados com `[seleção]` quando há 2+ e preview/calibração/ações seguem a linha destacada (senão a
  primeira ativa).
- O tray ganha start/stop agregados e um **submenu de start/stop por seleção**; soneca/silenciar/
  ciente são globais. `ui.max_sessions` (padrão 4, faixa 1..16) limita o conjunto;
  `runtime.session_already_running`/`runtime.session_limit` explicam as recusas. Remover uma seleção
  em execução para apenas a sessão dela.
- O `run` do CLI continua single-seleção de propósito (multi-ROI headless fica para a v1.0.0).

## Mudado

- `AlertChain.dispatch` consulta o gate antes da lista de canais; `DispatchOutcome` ganhou
  `SUPPRESSED_MANUAL`. `MonitorSession` ganhou `gate=`, `acknowledge()` e a propriedade
  `awaiting_ack`; `build_alert_chain(alerts, target_name, gate=None)`.
- `MonitorSession` grava evidência de mudança apenas em `FIRED`/`FAILED` (mudança de comportamento,
  ver acima).
- Eventos da GUI carregam `session`; `MainWindow`/tray passaram de uma sessão para o `SessionManager`
  (`actions(name)`, `preview(name)`, `calibration(name)`, `escalating(name)`, `stop(name)`).
- `edit-selection --mode` atualiza `overrides.mode` quando a chave existe (senão `selection.mode`);
  `--roi` limpa **os dois** campos de máscara pela regra de reedição de região.
- `features --json` ganhou a sonda de disponibilidade do `mqtt`.

## Atualizando

- Nada a migrar: seleções/YAML existentes continuam carregando; os canais novos são opt-in e a
  escalação vem `enabled: false` (comportamento anterior preservado). A mudança de evidência só reduz
  prints repetidos.
- Quem usa MQTT instala o extra: `pip install -e ".[mqtt]"` (os instaladores não o embutem). O ntfy
  funciona anônimo sem token; o SMTP precisa apenas das variáveis de ambiente de um relay
  autenticado.
- Soneca/silenciar são chaves novas do `state.json`; um `alerts_snooze_until` expirado é ignorado no
  start.
