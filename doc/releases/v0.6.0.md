# v0.6.0 — Selectable sound (MP3/M4A…) + text watch (appears/disappears)

Release notes for version **0.6.0** (minor: new sound backends and the `text_watch` filter). See also
[`CHANGELOG.md`](../../CHANGELOG.md) and the design in
[`doc/00 §10.4/§10.5/§11.2`](../00-Architecture_and_Specification.md).

## Added

### Selectable sound and more formats

The `sound` alert now plays **`.wav`, `.mp3`, `.m4a`, `.aac`, `.ogg`, `.oga`, `.flac`, `.wma`**
(depending on the available layer) instead of WAV only. Playback goes through the
`platform/audio.py` boundary, in this order:

1. **Qt** (`QMediaPlayer`/QtMultimedia) — **inside the GUI**: the player is created on the GUI thread
   and playback is queued to it (`QueuedConnection`), so the monitor loop thread never touches Qt.
   On Windows the backend is **Media Foundation** (WAV/MP3/M4A/AAC/FLAC/WMA); on Linux it is
   **GStreamer** (depends on the installed plugins).
2. **miniaudio** (now a **core dependency**) — **CLI/`run`** (no Qt application): WAV/MP3/OGG/FLAC;
   playback runs on a **daemon thread**, so it never blocks the loop. **No AAC/M4A**.
3. **Legacy fallback**: `winsound` (WAV only) on Windows; `paplay`/`aplay -q`/`ffplay`/`afplay` on
   Linux/macOS.

A missing file or a format with no decoder falls back to `beep()` **with a log warning** — never
silence nor an exception. A relative `file` is looked up in **`app-data/sounds/`** first and then in
the CWD (compatible with the previous behavior).

| Context | WAV | MP3 | OGG/FLAC | M4A/AAC |
|---|---|---|---|---|
| GUI on Windows (Media Foundation) | yes | yes | yes | **yes** |
| GUI on Linux (GStreamer, with plugins) | yes | yes | yes | depends on plugins |
| GUI on macOS (AVFoundation) | yes | yes | yes | yes |
| `run`/CLI (miniaudio) | yes | yes | yes | no — falls back to `ffplay` if installed, otherwise `beep` |
| Legacy without miniaudio | yes | no | no | no |

### GUI group “Detection and alerts”

Between the file buttons and “Session actions”:

- **Alert sound**: the effective `file` (from the profile/`sound` alert) is shown read-only;
  **Choose…** picks a file (`Audio (*.wav *.mp3 *.m4a *.aac *.ogg *.oga *.flac *.wma)` + *All files*),
  **Play** plays it through the Qt player and **Copy path** copies the `file: "<path>"` snippet to
  paste into the YAML. The selector **does not persist anything** — the YAML is read at start.
- **Watch text**: text field, **Action** (**Appears**/**Disappears**), **Match case** and
  **Ignore accents** checkboxes. It edits `overrides.text_watch` of the **currently selected**
  selection (like the mode selector), only enabled in **`advanced`** mode; switching the mode away
  from `advanced` **clears** the override (so the start does not fail validation).

### `text_watch` — alert when a text appears/disappears in the ROI

Enabled **only in `advanced`** (OCR). With a filter configured, the alert fires **only on the chosen
transition** (`expect: appears|disappears`); other text changes do not fire. Matching is
**substring**, `case_sensitive: false` and `ignore_accents: true` by default (NFKD + diacritics
removal on both sides — robust for pt-BR OCR).

Profile YAML (parity for CLI-only users):

```yaml
profiles:
  default:
    defaults:
      mode: "advanced"
      compare_options:
        advanced:
          similarity_threshold: 0.92
          text_watch: { text: "CONCLUÍDO", expect: "appears",
                        case_sensitive: false, ignore_accents: true }
```

Per-selection override (what the GUI writes; **takes precedence** over the profile):

```json
"overrides": { "text_watch": { "text": "CONCLUÍDO", "expect": "appears",
                               "case_sensitive": false, "ignore_accents": true } }
```

How it works, and the **phash gate bypass**: in `advanced` the phash (`default`) runs before the OCR
as a **pixel gate** (it only lets the OCR run when the pixels changed, which cut repeated false
positives). With a `text_watch`, that gate is **bypassed** — the OCR runs on every tick and the
filter verdict is authoritative: the OCR `changed` is **not** propagated and its `score`/`threshold`
stay only in the `detail` (visible in `compare-modes`). Without the bypass the gate would hide the
transition (when the pixels barely change, the OCR would not even run). Accepted cost: OCR on every
tick (100–500 ms; the default interval is 2 s).

The transition is a **definitive event**: it reports `severity: 3`, so an alert configured with
`severity_min: 3` still fires (a severity derived from the OCR score could stay below the minimum
and fail silently). Because the filter decides `changed`, **the actions also run only on the
configured transition** — the rest of the text changes are ignored. The behavior is the same as a
presence/absence (edge) filter, so the OCR noise that motivated the gate does not produce false
positives here.

## Changed

- **Selection**: a ROI that does not fit entirely inside the window is **rejected**
  (`runtime.roi_outside_window`) instead of saved with a warning (from the “Unreleased” batch).
- **`advanced` with the phash gate**: see above; without `text_watch` the behavior stays as shipped
  in the previous batch (`("default", "advanced")`).
- **Send test**: `test-alert` now reports `alert <id> failed: ...` and returns a non-zero exit code
  even when another channel (sound/popup) succeeded; `--only <id>` and the GUI button report a
  **missing token/URL** as a failure; `httpx`/`httpcore` no longer log the full URL (the Telegram
  token lives in it).

## Config error codes (new)

`config.text_watch_not_mapping`, `config.text_watch_text_required`,
`config.text_watch_invalid_expect`, `config.text_watch_not_bool`,
`config.text_watch_needs_advanced` — in both i18n catalogs (pt-BR/en-US).

## Upgrading

Nothing to migrate: existing YAML keeps working (without `text_watch`, the OCR gate behavior is
unchanged). `miniaudio` is now a **core dependency**, so the installers/`pip install` gain sound
support in the CLI (size impact) — the extra `sound` (`simpleaudio`) remains optional and is **not**
shipped.

**Bundle size impact (measured on the Windows onedir bundle):** `_miniaudio.pyd` ~0.6 MB plus the
QtMultimedia layer (`QtMultimedia.pyd` ~0.4 MB, `Qt6Multimedia.dll` ~1.2 MB and the `multimedia`
plugins — `ffmpegmediaplugin.dll` ~0.7 MB + `windowsmediaplugin.dll` ~0.3 MB) ≈ **+3 MB** in total.
The spec now lists `miniaudio` and `PyQt6.QtMultimedia` as explicit hidden imports; the PyQt6 hook
collects the `multimedia` plugins.
