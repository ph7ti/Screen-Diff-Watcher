# v0.9.0 — Reach: alerts, selections and multiple ROIs

Release notes for version **0.9.0** (minor: ntfy/SMTP/MQTT channels, snooze/mute + escalation, the
full selection lifecycle in the CLI — the README "Radar" item — and multiple simultaneous ROIs in the
GUI). See also [`CHANGELOG.md`](../../CHANGELOG.md) and the design in
[`doc/00 §1.4/§3.5/§3.7/§7.3/§11.2/§11.3/§11.5/§12.1/§12.2/§12.3/§12.4/§15/§16`](../00-Architecture_and_Specification.md).

## Added

### Alerts: ntfy, SMTP and MQTT

- **ntfy** (`httpx`): posts the rendered text to `server/topic` with `Title`, `Priority`
  (severity→1..5 mapping, default 3/4/5) and `Tags`; `attach_roi: true` switches to a PNG `PUT`
  (`Filename: roi.png`, text in the `Message` header). The token is optional and env-only
  (`token_env`, empty = anonymous topic).
- **SMTP** (stdlib `smtplib`): `security` may be `starttls` (default), `ssl` or `none`; credentials
  come from `username_env`/`password_env` (login only when the user variable exists) and never leak
  into errors/logs. `attach_roi` (default true) attaches the ROI PNG.
- **MQTT** (optional extra): `pip install -e ".[mqtt]"` (not bundled). `host`/`topic` required,
  `port` defaults to 1883 (8883 with `tls`), `qos` 0/1/2, `retain`, `client_id`, env credentials.
  A configured channel without the extra raises the visible `alert.mqtt_missing_extra` — never a
  silent skip. No image.
- All three follow the `options:` schema, `id`/`cooldown_s`/`severity_min`, payload templates and the
  sanitized-error rule. `test-alert --list/--only` prints the destination; `features --json` reports
  whether the `mqtt` extra is installed.

```yaml
alerts:
  - type: ntfy
    id: celular
    options: { server: "https://ntfy.sh", topic: "meu-topico", token_env: NTFY_TOKEN,
               attach_roi: true }
  - type: smtp
    id: email
    options: { host: "smtp.example.com", port: 587, security: starttls,
               from_addr: "watch@example.com", to: ["oncall@example.com"],
               username_env: SMTP_USERNAME, password_env: SMTP_PASSWORD }
  - type: mqtt
    id: barramento
    options: { host: "10.0.0.30", topic: "screen-watch/default", qos: 1,
               username_env: MQTT_USERNAME, password_env: MQTT_PASSWORD }
```

### Snooze/mute and escalation

- **Snooze…** (durations from `ui.snooze_minutes`, default 5/15/30/60) and **Mute/Unmute** in the
  Detection and alerts group, in the tray and (for `acknowledge`) as the optional
  `ui.hotkeys.acknowledge`. The shared `AlertGate` is thread-safe, applies to every session and
  persists in `state.json` (`alerts_snooze_until`, `alerts_muted`), so a later headless `run` inherits
  it until the snooze expires.
- While the gate is active, `dispatch` returns `SUPPRESSED_MANUAL` before trying any channel and the
  baseline is kept: the pending change alerts again when the snooze expires or the mute is lifted.
- **Escalation**: `defaults.escalation`/`overrides.escalation` (`enabled`, `severity_min`). On a
  `FIRED` outcome at `severity >= severity_min`, the baseline does **not** advance and the alert
  repeats at each channel's own `cooldown_s` until **Acknowledge** (`acknowledge()`), which re-arms
  the baseline. A status label shows "awaiting acknowledgement". Manual re-arm also clears it.
- **Change evidence is tied to delivery attempts**: `record_change` writes a print only on
  `FIRED`/`FAILED` (plus each escalation firing), instead of once per tick while suppressed.

### Selection lifecycle in the CLI (headless flow)

- `edit-selection NAME` edits without the overlay: `--mode`, `--roi X Y W H` (re-anchors
  `origin_at_selection` and clears both mask fields), `--mask X Y W H` (repeatable, replaces the
  effective masks), `--clear-masks`, `--poll-interval-s`, `--rearm/--no-rearm`, `--text-watch TEXT`
  `--text-expect appears|disappears`, `--clear-text-watch` and `--clear-override KEY`
  (`mode|poll_interval_s|rearm|masks|text_watch`). Writes atomically; errors leave the file intact.
- `rename-selection OLD NAME` reuses the GUI's `plan_rename`/`rename_selection` (slug, conflict and
  rollback rules); `remove-selection NAME...` deletes the files and clears `last_selection` when it
  pointed to a removed one; `list-selections --json` prints file/name/ROI/mode/effective-mask
  count/override keys for scripting.
- The README "Radar" item is resolved: `list-windows` → `select-manual` → `edit-selection` →
  `validate-config --selections` → `run --selection` covers the whole selection lifecycle.

```powershell
python -m screen_watch list-windows
python -m screen_watch select-manual --handle 123456 --roi 120 340 400 80 --name "painel erp"
python -m screen_watch edit-selection painel-erp --mode advanced --mask 10 10 40 20 \
  --poll-interval-s 1.5 --text-watch "CONCLUÍDO" --text-expect appears
python -m screen_watch validate-config --selections
python -m screen_watch run --selection painel-erp
```

### Multiple ROIs in the GUI

- New `gui/session_manager.py::SessionManager` runs **N sessions** (one `MonitorLoop`/thread/backend
  and preview/calibration buffers per selection) with a shared `AlertGate`. `MonitorController` was
  removed (no deprecation shim).
- The selection list has **checkboxes**: Start starts every checked selection (none checked = the
  highlighted row). Rows of running sessions get a `▶` prefix, the status line aggregates the count,
  log/result lines are prefixed with `[selection]` when 2+ run, and preview/calibration/actions
  follow the highlighted running row (else the first running one).
- The tray gets aggregated start/stop plus a **per-selection start/stop submenu**; snooze/mute/
  acknowledge are global. `ui.max_sessions` (default 4, range 1..16) bounds the set;
  `runtime.session_already_running`/`runtime.session_limit` explain refusals. Removing a running
  selection stops only its session.
- The CLI `run` intentionally stays single-selection (multi-ROI headless is a v1.0.0 follow-up).

## Changed

- `AlertChain.dispatch` checks the gate before the channel list; `DispatchOutcome` gained
  `SUPPRESSED_MANUAL`. `MonitorSession` gained `gate=`, `acknowledge()` and the `awaiting_ack`
  property; `build_alert_chain(alerts, target_name, gate=None)`.
- `MonitorSession` writes change evidence only on `FIRED`/`FAILED` (behavior change, see above).
- GUI events carry `session`; `MainWindow`/tray APIs moved from one session to `SessionManager`
  (`actions(name)`, `preview(name)`, `calibration(name)`, `escalating(name)`, `stop(name)`).
- `edit-selection --mode` updates `overrides.mode` when that key exists (else `selection.mode`);
  `--roi` clears **both** mask fields per the region re-edit rule.
- `features --json` gained the `mqtt` availability probe.

## Upgrading

- Nothing to migrate: existing selections/YAML keep loading; the new channels are opt-in and the
  escalation default is `enabled: false` (previous behavior preserved). The evidence change only
  reduces repeated prints.
- MQTT users install the extra: `pip install -e ".[mqtt]"` (the installers do not bundle it).
  ntfy works anonymously without any token; SMTP needs only the env variables for an authenticated
  relay.
- Snooze/mute are new `state.json` keys; an expired `alerts_snooze_until` is ignored on start.
