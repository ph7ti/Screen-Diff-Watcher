# v0.9.1 — GUI startup crash fix

Patch release for version **0.9.1** (fixes a regression introduced in 0.9.0: the GUI aborted on
startup). See also [`CHANGELOG.md`](../../CHANGELOG.md) and the design in
[`doc/00 §1.4/§3.7/§16`](../00-Architecture_and_Specification.md).

## Fixed

- **GUI crash on startup (0.9.0 regression)**: the v0.9.0 refactor replaced `MonitorController` with
  `SessionManager`, where `escalating` is a **method** (`escalating(name=None)`), but
  `main_window._update_gate_status` and `_acknowledge` still used the old property syntax. The
  resulting `TypeError` was raised inside the `QTimer` slot that drives `_drain`; PyQt6 aborts the
  process on an unhandled exception in a slot, so the GUI died on the very first tick (exit
  `0xC0000409` / `STATUS_STACK_BUFFER_OVERRUN`) with no visible traceback — users only saw the app
  disappear.
- The three call sites now use `self._controller.escalating()`. Verified by reproducing the crash
  from source, capturing the exact traceback, and confirming the fixed GUI stays up with a clean
  event loop.

## Notes

- New regression tests in `tests/test_gui_main_window.py` exercise the real
  `_update_gate_status`/`_acknowledge` methods with Qt-free stubs. The `main_window` import is lazy
  (inside a fixture) so the suite's tests that simulate Qt being unavailable
  (`tests/test_gui_countdown.py`, `tests/test_display.py`) keep passing.
- 689 unit tests; `ruff` and `validate-i18n` green. No behavior change beyond the fix.

## Upgrading

Nothing to migrate. If you installed 0.9.0, upgrade to 0.9.1 (the 0.9.0 GUI cannot start); the
config, selections and `state.json` are fully compatible.
