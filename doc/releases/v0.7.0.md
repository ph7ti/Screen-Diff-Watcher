# v0.7.0 — Selection name, on-screen highlight and region re-edit

Release notes for version **0.7.0** (minor: the selection gets a **display name** that also renames
the file, a **Highlight** action that shows the ROI without touching its pixels, and the
**double-click region re-edit**). See also [`CHANGELOG.md`](../../CHANGELOG.md) and the design in
[`doc/00 §3.7/§7.3/§12.3`](../00-Architecture_and_Specification.md).

## Added

### Selection name (and file rename)

The **Selections** group now has a **Selection name** field below the list. It is prefilled with
`selection.name or app_name or file stem`; confirm with **Rename** or **Enter**:

- The name is shown as a **prefix** in the list item
  (`verificando download - Selection Software XYZ — Region 120,340 400x80 — advanced`) and in the
  status/`run` output. The label keeps the **typed text** (case/accents).
- The **file is renamed** to the slug of the name: `selections/verificando-download.json`
  (`naming.slugify`: accents normalized, lower case, non-alphanumerics → `-`, max 60 chars).
- **Never overwrites** another selection: a slug that already exists (ignoring case) warns with
  `selection.name_conflict` and nothing changes. On failure the destination is removed (rollback,
  `selection.rename_failed`); the old file is only removed after the new one is written.
- `state.json:last_selection` is updated when it pointed to the old file name, and
  `list-selections` shows the custom name. **Scripts using `--selection <name>` must be updated to
  the new file name after a rename.**
- Renaming is **blocked while a session is running** (warning; nothing changes). An empty field keeps
  the current name. A name whose slug equals the current stem (e.g. only the case changed) is a
  **no-op that only records** `name`.

CLI parity: selections written by `select`/`select-manual` now also strip accents and cap the slug at
60 characters (same shared helper).

### Highlight ("Ver local")

The **Monitoring** group now uses a **two-column grid**: Start/Stop/Re-arm and Minimize to tray /
**Highlight**. Highlight draws the selected ROI on screen for **~2 s**:

- One frameless, *top-most* window **per monitor**, **transparent to clicks and focus** and
  non-modal (no keyboard/mouse grabs) — it never steals input.
- It dims **only outside the ROI** (four rectangles) and draws a 2 px border **just outside** the
  hole: **no pixel inside the ROI is painted**, so a monitoring tick cannot see the highlight as a
  change. Because of that it is safe to use **while the session runs** to check what is being
  watched.
- It closes by itself (`QTimer`) and needs a **compositor** on Linux for the translucency (without
  one the dim layer looks solid; the border is still drawn).

### Region re-edit (double-click)

**Double-clicking** a selection **re-opens the overlay** for its window and rewrites
`roi_relative`/`origin_at_selection`, preserving `name`, `mode`, `overrides`, `app_name` and
`window_title_hint`.

- The **masks are cleared** (log line): both `selection.masks` and `overrides.masks` are relative to
  the old ROI.
- The window is looked up **by handle**; if it is missing/minimized the GUI suggests **New Target**.
  A ROI that does not fit the window is rejected (`runtime.roi_outside_window`, same rule as the
  original selection).
- **Blocked while the session is running**; cancelling the overlay is a no-op (no error dialog).

## Changed

- **Behavior break — double-click**: it **no longer starts/stops** the monitoring; it **re-edits the
  region**. Use **Enter** on the list, the **Start/Stop** buttons, the tray or the global hotkeys to
  start/stop. `Enter` is bound with a `QShortcut` in the widget context (`itemActivated` is not used
  because it also fires on double-click).
- The GUI list/status and the CLI `run`/`list-selections` prefer the **name** over the file stem
  (`TargetConfig.label`), while `state.json:last_selection` and the action selection keep using the
  **stem**.

## Notes

- `Selection` (version 2) gained the optional `name`; older selections keep loading (the field
  defaults to empty) and no migration is needed.
- New error codes: `selection.name_invalid`, `selection.name_too_long`, `selection.name_conflict`,
  `selection.rename_failed` (both i18n catalogs). New i18n keys: `main.selection_name_label`,
  `main.btn_rename`, `main.btn_show_roi`, `highlight.label`, `dialog.rename_*`, `dialog.edit_running`,
  `dialog.reedit_window_missing` and `help.window.selection_name/show_roi`.
- New modules: `naming.py` (shared slug), `capture/roi.py` (single window+ROI resolution used by the
  capture and by the highlight) and `gui/highlight.py`. The capture (`_capture_target_roi`) and the
  highlight now share the same `resolve(window_info, roi_relative)` path.

## Upgrading

Nothing to migrate: existing selections/scripts keep working (a selection without a `name` shows the
old label). After renaming a selection, update any script that used `--selection <old-file-name>`.
