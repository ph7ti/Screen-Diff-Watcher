# v0.8.0 — Usability, observability and quality

Release notes for version **0.8.0** (minor: visual mask editor, sound written straight to the YAML,
frame preview, alert history, live calibration, and CI on Python 3.11/3.12/3.13 with coverage).
See also [`CHANGELOG.md`](../../CHANGELOG.md) and the design in
[`doc/00 §3.7/§8.3/§11.2/§12.1/§12.3/§12.4/§16`](../00-Architecture_and_Specification.md).

## Added

### Visual mask editor

- **Edit masks…** in the Selections row opens a transparent overlay per monitor over the target
  window: the ROI border and the effective masks are drawn; left-drag adds a mask, right-click removes
  the mask under the cursor, Enter saves and Esc cancels.
- Masks stay `[x, y, w, h]` **ROI-relative physical pixels** (they follow the window). Saving uses the
  effective-location rule: an existing `overrides.masks` is updated, else a non-empty `masks`, else
  `overrides.masks` is created (precedence over `masks`). The editor is **blocked while a session
  runs** and the selection JSON is now written **atomically** (temp + `os.replace`).
- Geometry is Qt-free (`gui/mask_editor_geometry.py`, tested at DPR 1.0/1.25/1.5).

### Sound written straight to the YAML

- After **Choose…**, the GUI asks for confirmation and **writes** `file:` into the first
  `type: "sound"` alert of the **active profile** (`config/loader.py::set_profile_sound_file`),
  creating the alert with the default shape when missing.
- The write is atomic and keeps `config.yaml.bak` (comments are not preserved); a failure leaves the
  original file intact. Config v1 is refused with `config.v1_not_editable` (run `migrate-config`); when
  the selected selection has `overrides.alerts`, the dialog warns that the profile value will not
  apply to it. **Copy path and open YAML / Open YAML only / Close** remain as secondary actions.

### Frame preview

- The Monitoring group shows the **baseline** and the **latest captured frame** while the session
  runs. Only downsampled thumbnails (<=240 px) cross the thread boundary; the loop's buffer is never
  handed to Qt and the GUI builds the `QImage` on its own thread.

### Alert history

- **History…** opens a table over `logs/alerts.jsonl` with date from/to, minimum severity and strategy
  filters, tolerant to invalid lines. **Open print** finds the nearest `*_change.png` within ±2 s of
  the alert (best effort); **Open prints folder** opens the captures folder. The record has no
  channel/target/evidence path, so the filters cover what the schema has.

### Live calibration

- **Calibration…** plots `score` vs `threshold` for **every** comparison (not only changes) from a
  bounded per-session ring buffer (600 samples), with points colored by severity and **Export CSV…**
  (timestamp, strategy, score, threshold, severity). No new dependency (custom `QPainter`).

### Quality

- The CI matrix now covers **Python 3.11, 3.12 and 3.13** on ubuntu/windows, running `pytest` with
  `--cov=screen_watch`; the `coverage-xml` artifact comes from the Linux/3.13 cell (report only, no
  gate).
- Wiki publication has a documented **manual runbook** (the wiki is a separate git repository);
  automatic publication is deferred until a `WIKI_PUSH_TOKEN` secret exists.

## Changed

- The old sound hint popup became a **confirmation dialog**; copying the snippet and opening the YAML
  remain available as secondary actions.
- `MonitorSession` gained optional `on_frame`/`on_compare` callbacks (default `None`); CLI/`run`
  behavior is unchanged.
- `dump_selection` is atomic; the region re-edit still clears the masks.

## Upgrading

Nothing to migrate. v1 configs keep working; the sound picker only writes to v2 YAMLs. Existing
`masks` in selections keep loading; the editor displays the effective list and writes to where it
lives.
