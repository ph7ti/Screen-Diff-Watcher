# v0.10.1 — DPI fix: GUI mouse locator and ROI highlight

Patch release for version **0.10.1** (bug fix). See also [`CHANGELOG.md`](../../CHANGELOG.md) and the
design in [`doc/00 §1.4/§5.1/§9.5`](../00-Architecture_and_Specification.md).

## Fixed

- **Clicks off target on monitors with scale ≠ 100%**: the action editor's mouse locator
  ("Locate mouse position…") returned the point in Qt **logical** space (e.g., 1536×960 on a physical
  1920×1200 @ 125% monitor), while the click runs in **physical** space (pynput/`SetCursorPos`) — the
  click landed at the logical coordinates (~192×120 px off at the screen center, growing toward the
  bottom-right corner). The locator now converts logical→physical anchored on the monitor under the
  cursor (origin + dpr), covering actions with `ref: roi`/`window`/`screen` created in the GUI.
- **"View region" highlight offset**: the highlight received the physical rect (from the capture path)
  and painted it in Qt logical coordinates; it now converts physical→logical per monitor before
  painting.
- **Wrong comment in `_locator_bases`**: the locator base is physical (not logical); code and
  docstring are aligned.

## Notes

- Capture/monitoring, the recorder (`record-actions`) and hand-typed coordinates were already in
  physical space and did not change — the bug was confined to the GUI path (locator + highlight).
- New pure helpers `point_to_physical`, `point_to_logical` and `rect_to_logical` in
  `gui/overlay_geometry.py`, with 5 new tests (conversions at 100%, 125%, 150% and 200%); verified
  live on a 1920×1200 @ 125% monitor with 0 px error at three sample points.
- No configuration migration; no new dependencies.
