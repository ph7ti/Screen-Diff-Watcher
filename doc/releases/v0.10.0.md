# v0.10.0 — Action scheduler (time triggers)

Feature release for version **0.10.0**. See also [`CHANGELOG.md`](../../CHANGELOG.md) and the design
in [`doc/00 §1.4/§3.5/§11.4/§12.2/§12.5/§14/§17`](../00-Architecture_and_Specification.md).

## Added

- **Per-action time triggers**: `when.trigger` selects what fires an action — `change` (default, the
  previous behavior) or `at`/`every`/`after`:
  - `at: ["HH:MM", ...]` (24 h) with optional `days` (`mon`..`sun`, the same names as
    `schedule.days`; missing = every day). Fires when the time is **crossed while armed**; times
    already passed that day do not fire and re-arming restarts the crossing reference.
  - `every_s >= 1`: the phase starts when armed and **restarts on each firing** (next due = firing +
    `every_s`); no bursts and no catch-up after sleep/suspension.
  - `after_s >= 1`: a single delay counted from arming; disarming cancels it, re-arming restarts.
- **Pure evaluator** `actions/triggers.py` with injectable wall (for `at`) and monotonic (for
  `every`/`after`, from `ArmingController.armed_since`) clocks; `ActionDispatcher.on_tick` evaluates
  the time triggers on every post-baseline frame even without a change, and
  `next_deadline_delay()` caps the `MonitorLoop` wait at `min(poll_interval_s, next deadline)` so
  `at` is punctual and `every_s` may be shorter than the poll.
- **Strict validation**: time triggers reject the `change` fields
  (`changed`/`severity_min`/`text_*`/`case_sensitive`) and `rebaseline: true`; `cooldown_s >=
  every_s` is an error; `at`/`days` are format-checked. All messages are translated (pt-BR/en-US).
- **GUI and CLI**: trigger selector in the action editor (time fields appear according to the
  choice), trigger summary in `list-actions`, recorder snippet with a commented hint of the time
  fields, and the one-off flows (`test-action`, "Run action (3s)") print
  `trigger ... ignored (explicit run)`.

## Behavior changes

- Every record in `logs/actions.jsonl` (and every live action event) now carries `trigger`
  (`change`/`at`/`every`/`after`).
- `ActionDispatcher.on_result` only evaluates actions with `trigger: change`; time-triggered actions
  never fire on a detected change.
- A time occurrence later than the **60 s tolerance** (sleep/suspend) is recorded as
  `skipped -> missed` and is **never executed**; there is no catch-up and no replay after restarting
  the app. Outside the `schedule` window, a due occurrence is consumed with `suspended_schedule`.
- Time triggers require the actions **armed** and have **no rehearsal** (the action editor hint
  states it).

## Notes

- 739 unit tests (50 new; the trigger evaluator is tested with fake clocks, no real sleeps);
  `ruff` and `validate-i18n` green.
- Documented limitations: `at` uses the naive local clock (DST can double or lose a firing);
  minimized/closed window = no frame = time triggers pause with everything else.
- No configuration migration: the new `when` fields are optional and `change` remains the default.
