# v0.11.0 — Passive update check, macOS build, installer consent and housekeeping

Feature release for version **0.11.0**. See also [`CHANGELOG.md`](../../CHANGELOG.md) and the design
in [`doc/00 §1.1/§1.4/§3.1/§3.2/§3.8/§5.1/§5.3/§12.1/§12.4/§15`](../00-Architecture_and_Specification.md).

## Added

- **Passive update check** (`src/screen_watch/updates.py`): once per GUI start, in a daemon thread,
  the app may perform **at most one anonymous `GET` per day** to
  `https://api.github.com/repos/ph7ti/Screen-Diff-Watcher/releases/latest` (`Accept:
  application/vnd.github+json`, 5 s timeout, no token). The result is cached in `state.json`
  (`update_check`: `checked_at`/`latest`/`url`/`notified_version`, 24 h TTL, failed attempts
  included) and only surfaces as a
  **log line + a tray item that opens the release** — no popup, no download and never on the
  capture/loop path. `ui.update_check: false` disables it; `parse_version`/`is_newer` are pure and
  tolerate `v`/suffixes; only `https` URLs on `github.com` are ever opened. The CLI stays offline.
- **macOS arm64 (unsigned)**: a `macos-latest`/3.13 CI cell (`QT_QPA_PLATFORM=offscreen`), the new
  `python scripts/build_release.py --macos` target (zip of `Screen Diff Watcher.app` via `ditto`,
  `build-info.json` with `target: macos` and `arch`), the PyInstaller `darwin` branch (`BUNDLE` with
  the GUI as `CFBundleExecutable`, `plyer.platforms.macosx.notification`) and a `macos` job in the
  release workflow publishing `screen-diff-watcher_<version>_macos_<arch>.zip`. Popups use the new
  `macosx` extra (`pyobjus`), installed by the CI/release jobs. **No signing/notarization**;
  validation on physical hardware (TCC permissions, tray, audio) is a v1.0.0 checklist item.
- **`mypy` (dev-only, core scope)**: pinned in the `dev` extra (`mypy==2.4.0`) with `[tool.mypy]` in
  `pyproject.toml` (no global `strict`, `ignore_missing_imports`) covering `capture/`, `compare/`,
  `config/`, `persistence/`, `platform/`, `errors.py` and `naming.py`; CI gate on the Linux/3.13
  cell.

## Changed

- **Windows installer**: Tesseract is now **optional with consent**. When it is missing, the
  interactive flow asks Yes/No (making clear that `light`/`default` work without it and only
  `advanced` needs it); silent installs (`/SILENT`/`/VERYSILENT`) **do not download by default** —
  only with `/TESSERACT=yes`. A helper failure (offline/SHA256/install) shows an informative message
  and **never aborts** the setup; in silent mode it continues without a dialog (no unattended hang).
  The SHA256 pin, `{app}\tools`, the `eng`+`por` validation and the
  uninstall that preserves Tesseract are unchanged.
- **Wayland spike decision**: the `org.freedesktop.portal.ScreenCast` + PipeWire route was evaluated
  (per-session consent/restore tokens, monitor/window streams) and **kept out of scope for the 1.x
  line**: frame delivery needs the system PipeWire stack plus GStreamer/`gi` (or libpipewire) with
  no mature, packageable client, and the portal does not provide the Model B anchored ROI. The
  current detection/warning stays; a future backend would live behind `capture/backend.py`.
- **CI/release**: the test matrix now includes macOS; `python -m mypy` runs on Linux/3.13; the PR
  `package` job also builds the macOS bundle; `release.yml` publishes Windows/Linux/macOS.

## Removed

- The unused `logging` extra (`structlog`): structured logging adoption was rejected; the stdlib
  `logging` stays.

## Notes

- 770 unit tests (21 new in `tests/test_updates.py`, plus config/GUI tests); `ruff`, `mypy`,
  `validate-i18n` and the suite are green. No new runtime dependency (`httpx` was already core;
  `pyobjus` is the macOS-only `macosx` extra).
- Failed checks also honor the 24 h TTL (no offline polling) and only `https` URLs on `github.com`
  are opened by the tray item.
- The Windows bundle was rebuilt and smoke-tested (`features --json`) with the changed spec; the
  Tesseract consent flow on a real install and the macOS hardware validation remain in the v1.0.0
  manual checklist.
- v1.0.0 is now only **manual validation + closing**; the deferred follow-ups are listed in the
  roadmap (`.kilo/knowledge/roadmap.md`).
