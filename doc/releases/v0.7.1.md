# v0.7.1 — Layout reflow, bundled default sound and sound popup

Release notes for version **0.7.1** (patch: the window is repaginated into a 2×2 grid, the default
sound is now a bundled `alert.mp3`, and choosing a sound opens a helper popup). See also
[`CHANGELOG.md`](../../CHANGELOG.md) and the design in
[`doc/00 §3.7/§11.2/§12.4`](../00-Architecture_and_Specification.md).

## Added

### Bundled default sound (`alert.mp3`)

The default `file` of `sound` alerts is now **`"alert.mp3"`**, and that file ships with the package
in `screen_watch/assets/sounds/` (declared in `package-data` for the wheel and in the PyInstaller
`datas`). The resolver `platform/audio.py::resolve_sound_path` now checks, for a relative `file`:

1. `app_home()/sounds` (the user folder — always wins);
2. `resources.bundled_sounds_dir()` (`screen_watch/assets/sounds`);
3. the CWD (legacy behavior).

Absolute paths are used as-is. Existing configs with `alert.wav` (or any other path) are **not
changed**; the new default only applies to new configs or when the user edits the line. A missing file
still falls back to `beep()`.

### Sound-choice popup

After each **Choose…** the GUI opens a modal hint explaining where to paste the copied snippet: it
points to `config.yaml`, the desired profile (quoting the **active profile**) and the `type: "sound"`
alert, with three buttons — **Copy path and open YAML** (default), **Open YAML only** and **Close**
(`dialog.sound_*`, both i18n catalogs).

### Window repagination

The upper panel is now a **2×2 grid** following the `UI.txt` mockup:

- **(0,0) Selections** — New Target / Remove / Reload / **Highlight selection** row, legend, list and
  the **Selection name** field + Rename.
- **(0,1) Monitoring** — two-column grid: Start/Language, Stop/Re-arm baseline, Mode/Profile,
  Arm actions/Disarm actions, Arm for…/Minimize to tray, plus **Record captures (evidence)** and the
  arming status.
- **(1,0) Session actions** — list, counter and the horizontal New action…/Edit…/Remove Action/Run
  action row.
- **(1,1) Detection and alerts** — the text watch first, then the sound (read-only snippet field and
  Choose…/Play/Copy path).

The footer (`QSplitter`) is a **Status** group with Status/Last/Log, and the right column holds
**Captures / Test alert… / Open YAML**.

## Changed

- **Highlight selection** moved from Monitoring to the Selections button row; **Record captures
  (evidence)** moved into Monitoring.
- GUI labels: **Highlight selection**, **Arm actions** and **Disarm actions**.
- The sound field now shows the `file: "..."` snippet directly (the separate snippet label was
  removed); **Copy path** and **Play** are disabled when there is no value.

## Notes

- The bundled sound lives in `src/screen_watch/assets/sounds/alert.mp3` (single versioned copy);
  `resources.py` gained `bundled_sounds_dir()`/`default_sound_path()`.
- New i18n keys: `dialog.sound_title/sound_help/sound_copy_open/sound_open_only/sound_close` (both
  catalogs). `_copy_sound_snippet` now builds the snippet from the chosen/effective file instead of
  reading the removed label.
- **Versioning note**: `0.7.0 → 0.7.1` is a conscious **PATCH** choice (the documented SemVer rule
  would suggest MINOR — but these are layout/UX and default-sound changes with no API or data break).

## Upgrading

Nothing to migrate. Existing configs keep their `file` (e.g. `alert.wav`); to use the bundled sound,
set the `sound` alert `file:` to `"alert.mp3"` (or remove the `file:` line to accept the default).
