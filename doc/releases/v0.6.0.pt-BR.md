# v0.6.0 — Som selecionável (MP3/M4A…) + verificação de texto (aparece/desaparece)

Notas de release da versão **0.6.0** (minor: novos backends de som e o filtro `text_watch`). Veja
também o [`CHANGELOG.md`](../../CHANGELOG.md) e o design em
[`doc/00 §10.4/§10.5/§11.2`](../00-Documento_de_Arquitetura_e_Especificação.md).

## Adicionado

### Som selecionável e em mais formatos

O alerta `sound` agora toca **`.wav`, `.mp3`, `.m4a`, `.aac`, `.ogg`, `.oga`, `.flac`, `.wma`**
(conforme a camada disponível), não só WAV. A reprodução passa pela fronteira
`platform/audio.py`, nesta ordem:

1. **Qt** (`QMediaPlayer`/QtMultimedia) — **na GUI**: o player é criado no thread da GUI e a
   reprodução é enfileirada para ele (`QueuedConnection`), de modo que a thread do loop de
   monitoramento nunca toca em Qt. No Windows o backend é o **Media Foundation**
   (WAV/MP3/M4A/AAC/FLAC/WMA); no Linux, o **GStreamer** (depende dos plugins instalados).
2. **miniaudio** (agora **dependência core**) — **CLI/`run`** (sem aplicação Qt):
   WAV/MP3/OGG/FLAC; a reprodução roda numa **thread daemon**, sem bloquear o loop. **Sem AAC/M4A**.
3. **Fallback legado**: `winsound` (só WAV) no Windows; `paplay`/`aplay -q`/`ffplay`/`afplay` no
   Linux/macOS.

Arquivo ausente ou formato sem decoder cai no `beep()` **com aviso no log** — nunca silêncio nem
exceção. `file` relativo é procurado em **`app-data/sounds/`** primeiro e depois no CWD (compatível
com o comportamento anterior).

| Contexto | WAV | MP3 | OGG/FLAC | M4A/AAC |
|---|---|---|---|---|
| GUI no Windows (Media Foundation) | sim | sim | sim | **sim** |
| GUI no Linux (GStreamer, com plugins) | sim | sim | sim | depende dos plugins |
| GUI no macOS (AVFoundation) | sim | sim | sim | sim |
| `run`/CLI (miniaudio) | sim | sim | sim | não — cai no `ffplay` se instalado, senão `beep` |
| Legado sem miniaudio | sim | não | não | não |

### Grupo “Detecção e alertas” na GUI

Entre a linha de botões e “Ações da sessão”:

- **Som do alerta**: o `file` efetivo (do perfil/alerta `sound`) aparece em modo leitura;
  **Escolher…** seleciona um arquivo (`Audio (*.wav *.mp3 *.m4a *.aac *.ogg *.oga *.flac *.wma)` +
  *All files*), **Reproduzir** toca pelo player Qt e **Copiar caminho** copia o trecho
  `file: "<caminho>"` para colar no YAML. O seletor **não persiste nada** — o YAML é lido ao iniciar.
- **Verificar texto**: campo de texto, **Ação** (**Aparece**/**Desaparece**), checkboxes
  **Diferenciar maiúsculas** e **Ignorar acentos**. Edita `overrides.text_watch` da **seleção atual**
  (como o seletor de modo), habilitado **somente** no modo `advanced`; trocar o modo para fora do
  `advanced` **limpa** o override (o start não falha na validação).

### `text_watch` — alertar quando um texto aparece/desaparece na ROI

Disponível **somente no `advanced`** (OCR). Com o filtro configurado, o alerta dispara **somente na
transição** escolhida (`expect: appears|disappears`); as demais mudanças de texto não disparam. O
casamento é por **substring**, com `case_sensitive: false` e `ignore_accents: true` por padrão
(NFKD + remoção de diacríticos nos dois lados — robusto para OCR em pt-BR).

YAML do perfil (paridade para quem usa só CLI):

```yaml
profiles:
  default:
    defaults:
      mode: "advanced"
      compare_options:
        advanced:
          similarity_threshold: 0.92
          text_watch: { text: "CONCLUÍDO", expect: "appears",
                        case_sensitive: false, ignore_accents: true }
```

Override por seleção (o que a GUI grava; **tem precedência** sobre o perfil):

```json
"overrides": { "text_watch": { "text": "CONCLUÍDO", "expect": "appears",
                               "case_sensitive": false, "ignore_accents": true } }
```

Como funciona, e o **bypass do gate de phash**: no `advanced` o phash (`default`) roda antes do OCR
como **gate de pixel** (só deixa o OCR rodar quando os pixels mudaram, o que cortou falsos
positivos repetidos). Com um `text_watch`, esse gate é **bypassado** — o OCR roda a cada tick e o
veredito do filtro é autoritativo: o `changed` do OCR **não** é propagado e `score`/`threshold`
dele ficam apenas no `detail` (visível no `compare-modes`). Sem o bypass o gate esconderia a
transição (quando os pixels mudam pouco, o OCR nem rodaria). Custo aceito: OCR a cada tick
(100–500 ms; o intervalo default é 2 s).

A transição é um **evento definitivo**: reporta `severity: 3`, de modo que um alerta configurado com
`severity_min: 3` ainda dispara (uma severidade derivada do score do OCR poderia ficar abaixo do
mínimo e falhar em silêncio). Como o filtro decide o `changed`, **as ações também só rodam na
transição** configurada — o restante das mudanças de texto é ignorado. O comportamento é o de um
filtro de presença/ausência (borda), então o ruído de OCR que motivou o gate não gera falso
positivo aqui.

## Mudado

- **Seleção**: uma ROI que não cabe inteiramente na janela é **rejeitada**
  (`runtime.roi_outside_window`) em vez de salva com um aviso (lote “Unreleased”).
- **`advanced` com o gate de phash**: veja acima; sem `text_watch` o comportamento segue o do lote
  anterior (`("default", "advanced")`).
- **Teste de envio**: o `test-alert` agora reporta `alert <id> failed: ...` e retorna código != 0
  mesmo que outro canal (som/popup) tenha funcionado; `--only <id>` e o botão da GUI reportam
  **token/URL ausentes** como falha; `httpx`/`httpcore` não logam mais a URL completa (o token do
  Telegram vive nela).

## Códigos de erro novos

`config.text_watch_not_mapping`, `config.text_watch_text_required`,
`config.text_watch_invalid_expect`, `config.text_watch_not_bool`,
`config.text_watch_needs_advanced` — nos dois catálogos i18n (pt-BR/en-US).

## Atualização

Nada a migrar: o YAML existente continua funcionando (sem `text_watch`, o comportamento do gate do
OCR não muda). O `miniaudio` passa a ser **dependência core**, então instaladores/`pip install`
ganham som no CLI (impacto de tamanho) — o extra `sound` (`simpleaudio`) segue opcional e **não** é
empacotado.

**Impacto de tamanho no bundle (medido no onedir do Windows):** `_miniaudio.pyd` ~0,6 MB mais a
camada QtMultimedia (`QtMultimedia.pyd` ~0,4 MB, `Qt6Multimedia.dll` ~1,2 MB e os plugins
`multimedia` — `ffmpegmediaplugin.dll` ~0,7 MB + `windowsmediaplugin.dll` ~0,3 MB) ≈ **+3 MB** no
total. O spec agora lista `miniaudio` e `PyQt6.QtMultimedia` como hidden imports explícitos; o hook
do PyQt6 coleta os plugins de `multimedia`.
